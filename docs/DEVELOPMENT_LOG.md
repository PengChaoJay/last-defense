# 开发日志

本文记录《最后的防线》从想法到可玩 MVP 的关键变化、技术决策、测试结果和后续计划。

## 2026-11-09：核心原型

### 完成

- 创建 Godot 4.7.2 工程和 Git 仓库。
- 实现 WASD / 方向键移动。
- 实现敌人生成、追踪、接触伤害和死亡。
- 实现自动索敌、能量弹和基础战斗。
- 加入能源核心，形成“玩家和核心双重生存”目标。
- 增加失败、结算和重开流程。

### 决策

第一版不使用复杂场景树和正式素材，而是通过一个 `Node2D` 和程序绘制快速验证玩法。

### 结果

完成“移动—自动攻击—保护核心—失败—重开”的第一条闭环。

## 2026-11-09：成长、武器与 Boss

### 完成

- 增加经验晶体、等级和升级三选一。
- 增加九类升级卡。
- 增加能量炮、电弧模块和环绕刀片。
- 增加连锁脉冲和过载旋刃两种融合。
- 增加普通、快速、重型、精英和 Boss 敌人。
- Boss 支持追踪、召唤和冲锋。
- 第 7 分钟进入 Boss 战，第 10 分钟超时失败。

### 决策

前两次升级优先提供新武器，避免玩家因为随机性长时间体验不到构筑差异。

### 测试

建立 `tests/smoke_test.gd`，覆盖武器融合、Boss 生成和关键战斗路径。

## 2026-11-10：表现层与生成素材

### 完成

- 增加标题、暂停、升级和结算界面。
- 增加屏幕震动、受击闪光、伤害数字和低生命警告。
- 增加星空背景、核心脉冲和系统提示。
- 使用 Python 生成射击、命中、受伤、拾取、升级、Boss 和胜利音效。
- 生成并接入玩家、普通敌人、重型敌人、Boss 和能源核心贴图。
- 建立贴图裁切与缩放工具。

### 决策

保留生成原图，同时创建统一的 256×256 游戏版本。玩法逻辑只引用游戏版本，便于未来替换正式美术。

### 风险

当前生成图片和音效仍属于占位资源，正式发行前需要再次确认许可、风格一致性和平台规则。

## 2026-11-10：动态防守关卡

### 完成

- 增加六个机械柱和圆形碰撞。
- 增加敌人轻量绕障。
- 增加腐蚀区和减速区。
- 增加核心维修、武器超载和医疗终端。
- 增加核心突袭、精英入侵和终端重置事件。
- 增加 Boss 冲锋预警线。

### 决策

没有立即引入完整 `NavigationRegion2D`，而是使用方向排斥和穿透修正，满足单屏竞技场需求。未来如果加入迷宫或多房间，再迁移到正式导航系统。

### 结果

玩家不再只围绕核心绕圈，需要在防守、躲避危险和前往地图边缘使用终端之间做选择。

## 2026-11-12：稳定性、持久化与流程优化

### 问题

- 敌人、子弹、经验、粒子和伤害数字没有硬上限，极端长局可能持续增长。
- 游戏没有保存最佳战绩。
- 暂停和结算界面无法返回标题页。
- 音效开关不会跨启动保存。

### 完成

- 普通敌人上限：180。
- 子弹上限：320。
- 经验晶体上限：260。
- 粒子上限：520。
- 伤害数字上限：140。
- 电弧特效上限：80。
- 超出视觉对象上限时优先移除最旧对象。
- 使用 `ConfigFile` 保存最佳击杀、最长生存、完成局数、胜利次数和音效设置。
- 标题页和结算页显示战绩。
- 暂停或结算时按 `Q` 返回标题页。
- 统一使用 `finish_run()` 处理胜利、失败、统计和存档，避免重复结算。
- 扩展冒烟测试，验证敌人和粒子上限。

### 技术说明

存档位于 Godot 的 `user://last_defense_save.cfg`，不写入项目仓库。删除该文件可以清空本地战绩。

## 当前已知问题

1. `main.gd` 职责过多，继续扩展前应逐步拆分。
2. 自动索敌仍会线性遍历敌人数组。
3. 敌人绕障适合单屏圆形障碍，不适合复杂迷宫。
4. 尚未建立正式对象池，目前使用数量上限控制峰值。
5. 数值尚未经过足够数量的外部玩家验证。
6. 缺少正式 Windows 导出包和公开试玩数据。

## 下一步建议

优先级从高到低：

1. 邀请 5～10 名玩家完成第一轮封测。
2. 记录主动重开率、常用构筑、死亡时间和终端使用率。
3. 根据数据调整前两分钟节奏和 Boss 生命。
4. 将升级配置迁移为 Resource。
5. 拆分玩家、敌人、武器和 UI 场景。
6. 使用 Godot Profiler 决定是否需要空间索引和对象池。
7. 导出 Windows Demo 并创建 GitHub Release。
